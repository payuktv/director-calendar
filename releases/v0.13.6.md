# v0.13.6

Protect backup restoration and startup from untrusted SQLite schemas, ship a patched SQLite runtime, and remove obsolete program files during upgrades.

- Validate application-owned table definitions before querying backup data, running integrity checks or migrating it. Reject triggers, views, virtual tables, generated columns, expression/partial indexes and altered constraints/defaults. Both restoration paths and startup use the same gate, including a second check of staging files. Compatible historical copies retain their events, frozen plans, facts, notes, history and sequence numbers.
- Enable SQLite defensive mode and disable trusted schema behavior. Inspect copies read-only with triggers/views disabled, SQL/value limits, a 512 MiB database limit, a 15-second validation budget and a 30-second copy budget. Failed validation leaves the working database intact.
- Ship official SQLite 3.54.1 for Windows x64, pinned to its upstream SHA3-256 and verified source ID. Replace the old DLL collected from CPython. Windows tests use the same library; packaged acceptance and publication require the actual runtime version/source ID.
- Delete only explicitly retired files from older installers, including the unused Qt libraries left by upgrades to v0.13.5. Preserve unrelated files and reject installation paths containing reparse points. Acceptance compares installed file hashes after upgrade and reinstall and checks historical leftovers, user files, and junction protection.
- Retain complete Windows/Linux release tests and native installer, update, backup, credentials and uninstall acceptance.

Close the application and install `DirectorCalendar-0.13.6-Setup-x64.exe`. This is an unsigned pre-release; installation remains manual. Databases with externally modified SQL schemas are rejected rather than repaired automatically.
