# v0.13.2

Fix deleted Mail.ru events remaining in the current unfrozen schedule.

- Request CalDAV resource types and recognize the selected calendar collection in Mail.ru query responses. A verified collection's missing calendar-data property no longer falsely makes the import partial.
- Continue treating unreadable event resources, unknown collection types, foreign addresses and access failures conservatively. Do not send credentials outside the selected collection.
- After a complete sync, withdraw missing unprotected events starting today or later, including events earlier today. Use the configured display time zone. Keep earlier calendar dates, frozen plans, actual time, manual statuses and comments protected.
- Preserve withdrawn identities and audit history; a source reappearance restores the same record. Open withdrawn records from History in a read-only card without inventing schedule times.

Close the application and install `DirectorCalendar-0.13.2-Setup-x64.exe`, then refresh Mail.ru for the affected dates. Only the loaded period is reconciled. A genuinely partial import still does not withdraw events.

This remains a pre-release before v1.0.0 acceptance. Updates are manual and the installer remains unsigned.
