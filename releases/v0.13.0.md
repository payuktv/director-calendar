# v0.13.0

Runtime error diagnostics for Director Calendar. This is a pre-release; v1.0.0 remains reserved for production acceptance.

## Changes

- Add a local rotating error log for startup, unhandled Python/Qt errors, background Python threads and handled application failures.
- Record operation codes, exception types and code locations without exception messages, source lines, local variables, credentials or calendar contents.
- Keep the current log and three rotated files, approximately 1 MiB each. Logging failures do not interrupt the original operation.
- Add Settings → Diagnostics with buttons to open the log folder and copy its path. Nothing is uploaded automatically.
- Show a generic notice after an unhandled runtime error and stop writing raw startup tracebacks to the legacy startup log.
- Verify logging and secret omission inside the packaged Windows executable; test upgrading from the published v0.12.1 source.

## Install or update

Close Director Calendar and run `DirectorCalendar-0.13.0-Setup-x64.exe`. Python and administrator privileges are not required. Existing data/settings and saved credentials are preserved; the application creates its verified backup before opening the database with the new version.

For portable use, extract the entire `DirectorCalendar-0.13.0-portable-x64.zip` into a new directory. Logs use the existing AppData data location, alongside the database directory, not the program directory.

## Diagnostics and limitations

The default log path is `%LOCALAPPDATA%\DirectorControl\logs\director-calendar.log`. UTC timestamps and code locations help identify failures; messages and application data are omitted intentionally. A native crash, forced termination or power loss may not create a log entry. Old `startup-error.log` files remain untouched and are no longer written by this version.

The installer remains unsigned. Real-account Mail.ru and clean target-Windows acceptance are still required before v1.0.0. Updates are installed manually.
