# v0.13.10

Release candidate for v1.0.0 with a frozen feature scope and finite acceptance checklist.

- Share field validation between calendar ingestion, storage and startup. Reject whitespace-only or malformed UIDs and invalid event text before saving any part of a snapshot. A rejected import leaves the existing database unchanged; valid identities are preserved without trimming or rekeying.
- Apply the same rules to local event/category writes and synchronization metadata. Keep accepted records valid after restart, including cancelled events retained after source removal. Add regression coverage for transport, the real parsing worker, storage rollback and reopen behavior.
- Use one XML policy in production CalDAV parsing and runtime acceptance. DTDs, entities and external references are explicitly forbidden, including a harmless DTD without entities.
- Require the shipped executable to pass write/reopen acceptance before publication. Keep the full Windows/Linux suites and all existing distribution gates mandatory.
- Update installation examples and document the remaining target-system acceptance for v1.0.0. Signing, automatic updates and other improvements are tracked separately from the frozen release scope.

Close the application and install `DirectorCalendar-0.13.10-Setup-x64.exe`. Installation remains manual. Existing valid databases and backup preferences are preserved; the schema remains version 4. Python 3.14.10, Expat 2.10.0, SQLite 3.54.1 and OpenSSL 3.5.9 remain unchanged.

This candidate is published as a pre-release until the documented target-system acceptance is recorded. The installer is unsigned. No calendar events are written to Mail.ru. General audits and additional features are not prerequisites for promoting the accepted scope to v1.0.0.
