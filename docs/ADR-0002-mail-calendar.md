# ADR-0002: Чтение календаря Mail.ru

Дата: 22.10.2026. Версия приложения: 0.2.0.

## Решение

Используется конкретная CalDAV-коллекция, указанная пользователем, и полный логин почты. Пароль внешнего приложения вводится только на его компьютере. Учётные данные и реальный календарь не используются в CI.

Транспорт выполняет HTTPS REPORT с Depth: 1 к `calendar.mail.ru`. В версии 0.2.2 при `calendar-data 404` добавлено отдельное чтение GET по href только внутри выбранной коллекции. Переходы на другие хосты и коллекции, учётные данные/параметры в ссылке и редиректы запрещены. TLS проверяется стандартным механизмом requests, внешние настройки .netrc и прокси не подхватываются. Установлены таймауты, общий предел объёма REPORT+GET, временной бюджет и лимит 50 отдельных запросов. XML разбирает defusedxml. Ошибки не включают пароль, href, сетевые исключения или тело ответа.

`icalendar` разбирает VCALENDAR; `recurring-ical-events` разворачивает RRULE/RDATE/EXDATE и отдельные исключения в периоде 30 дней до и 90 дней после выбранной даты. UID + исходный RECURRENCE-ID + идентичность календаря/аккаунта дают стабильный ключ. Время приводится к Europe/Moscow по умолчанию; Windows получает базу часовых поясов через tzdata. Данные с неподдерживаемым форматом останавливают весь импорт.

Установка и запрос выполняются без сервиса CalDAV с возможностями записи: узкий транспорт легче проверить на отсутствие PUT/DELETE. Библиотека `caldav` из ADR-0001 остаётся возможным будущим вариантом для discovery и протокольного sync-token, когда появится такая необходимость.

## Данные и изменения

Схема SQLite версии 2 добавляет таблицу метаданных `calendar_events`; исходные таблицы и записи версии 0.1 сохраняются. Перед обновлением пользователь создаёт резервную копию существующей базы штатной кнопкой. Более новая неизвестная версия БД отвергается.

Импорт одного полного ответа транзакционный. Источник управляет названием и актуальным временем. Категория, факт, комментарий и явно изменённый локальный статус сохраняются. Зафиксированный исходный план не обновляется.

Если отдельное свойство calendar-data имеет 404 и запись не удаётся прочитать по GET, остальные прочитанные записи применяются одной транзакцией, но результат явно отмечается как частичный. В этом случае обнаружение исчезновений отключено, старые записи остаются, а время последней полной синхронизации не меняется. При отсутствии любых прочитанных ресурсов или при ошибке сети/XML/разбора импорт не выполняется. Свойство calendar-data 403 по-прежнему прерывает обновление; ошибка GET отдельной записи показывается в предупреждении. Тело ошибочного GET не используется.

Явный STATUS:CANCELLED меняет статус только без локального переопределения; в остальных случаях состояние источника видно отдельно. Отсутствие события в ограниченном ответе **не является доказанным удалением**: запись отмечается как требующая проверки, история и факт остаются. Новые события не получают исходный план автоматически.

События на весь день не закрывают временные окна 07:00–19:00 и не добавляют 24 часа планового времени. Их категория по умолчанию исключена из контроля выполнения. Замена коллекции или часового пояса после импорта пока запрещена.

## Интерфейс и секреты

QThread получает и разбирает ответ; основной GUI-поток применяет результат и обновляет таблицы. Параллельный запуск второй синхронизации блокируется. Закрытие окна во время запроса откладывается до завершения, чтобы не уничтожить работающий поток.

Пароль хранится в памяти процесса; при выборе сохранения на Windows используется явно `WinVaultKeyring`, без выбора запасного backend и без plaintext fallback. Пароль не записывается в SQLite/конфигурацию/логи. Отключение сохранения удаляет запись из Windows Vault, оставляя пароль только до закрытия программы.

## Проверки и границы

Автоматические проверки охватывают повторы, перенос исключения, DST, весь день, отмену, исчезновение/возвращение, повторный импорт, миграцию и откат транзакции, транспорт и защиту секретов. Отдельно проверяется фоновая загрузка с обновлением GUI.

Эти проверки используют вымышленные ответы. Реальное подключение к данной учётной записи требует локального ввода пароля и контрольного импорта; до этого совместимость именно с этим календарём не подтверждена. Автоматического периодического опроса, обратной записи и смены подключённого календаря нет.
