# ADR-0001: Технологический стек первой версии

**Дата:** 22.10.2026  
**Статус:** принято для прототипа, подлежит проверке на Windows.

## Контекст

Требуется локальная система для бизнес-ассистента генерального директора: расписание 07:00–19:00, начальный и актуальный план, факт, отклонения, история, аналитика; в перспективе — только чтение CalDAV-календаря Mail.ru. Один пользователь, Windows 10/11, без необходимости в сервере.

## Решение

| Уровень | Стек | Почему |
|---|---|---|
| Язык | Python 3.13 | Зрелая поддержка библиотек; актуальная поддерживаемая ветка на дату решения |
| UI | PySide6 6.12.0 / Qt Widgets | Современный Qt 6, нативный desktop UI, таблицы и формы; поддержка Win10/11 |
| Хранилище | SQLite + стандартный `sqlite3` | Транзакции, локальная БД, отсутствие внешнего сервера |
| Модель данных | Отдельный модуль `storage.py` | Тестируется отдельно от интерфейса; можно заменить backend без переписывания UI |
| Тесты | pytest + GitHub Actions | Проверка правил и smoke-тест окна на Windows |
| Сборка | Официальный `pyside6-deploy` / Nuitka | Создание автономной папки с .exe, не нужно устанавливать Python конечному пользователю |
| Будущий календарь | CalDAV-адаптер в отдельном модуле | Mail.ru поддерживает протокол, но доступ и форматы событий требуют проверки |

## Рассмотренные альтернативы

- **Streamlit:** очень быстрый UI, но запускает локальный веб-сервер и браузер; сложнее создавать привычное desktop-поведение и таблицы с редактированием. В качестве основного UI не выбран.
- **Electron + React:** современный интерфейс, но добавляет JavaScript/Node.js, браузерный runtime, web/desktop bridge и дополнительную инфраструктуру сборки. Для одного пользователя и табличной программы избыточен.
- **Tauri + React:** относительно компактнее Electron, но добавляет Rust и webview-зависимости; для быстрого рабочего прототипа больше новых технологий и потенциальных проблем сборки.
- **Tkinter:** нет внешней зависимости, но уступает Qt в возможностях сложных таблиц и развитии интерфейса.
- **PostgreSQL:** оправдан для сервера или нескольких одновременных пользователей, но для одного ПК добавляет обслуживание и риски эксплуатации.
- **SQLAlchemy:** полезен для сложной доменной модели и миграций, но пока SQLite и параметризованные SQL-запросы дают менее сложную основу. Миграции схемы — обязательный следующий шаг при расширении БД.
- **Python 3.15:** самый новый релиз, но нет причины выбирать его ради пилота, когда не все desktop-инструменты прошли массовую проверку в корпоративных Windows-средах.

## Ограничения и проверка готовности

1. Компонент БД должен проходить unit-тесты до подключения реального календаря.
2. GUI должен открываться и корректно редактировать события на целевой Windows-машине.
3. Исполняемая сборка должна успешно пройти smoke-тест в Windows.
4. CalDAV-синхронизацию подключаем сначала только в режиме чтения на тестовом календаре, с защитой исходного плана, дедупликацией UID/recurrence-id, поддержкой TZID и повторов.
5. Рабочие данные руководителя остаются локальными, не попадают в GitHub или в логи CI.
6. После появления нескольких версий схемы добавить миграции БД и тест отката/восстановления резервной копии.

**Вывод:** стек реалистичен и проверяем поэтапно. Абсолютную гарантию совместимости с неизвестной конфигурацией Windows и реальным календарём Mail.ru до их испытания давать нельзя.
